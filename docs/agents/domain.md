# Documentação de domínio

O projeto usa um único contexto.

Antes de explorar o código, lê `GLOSSARY.md` na raiz e os documentos
em `docs/adr/` relevantes para a área de trabalho.

Se não existirem, continua sem os criar ou sugerir a sua criação.
A skill `domain-modeling` cria-os quando forem definidos termos
ou tomadas decisões.

Usa os termos do glossário em tarefas, propostas e testes.
Se faltar um conceito necessário, regista a lacuna para
`domain-modeling`.

Se uma proposta contrariar uma decisão documentada num ADR,
identifica explicitamente o conflito e explica a razão.
